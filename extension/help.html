⌘ claude code inspector
Pick elements on any page, describe the change, and let Claude Code edit your project files. Here's how to get everything running.

1Start the bridge

The extension talks to a small local server (the bridge) that runs Claude Code against your project. Start it in a terminal and leave it running:

# from the claude-code-inspector repo
cd bridge
npm install        # first time only
node server.js

On startup the bridge prints an auth token:

✓ Bridge listening on http://localhost:3131

🔑 Auth token (paste it in the extension side panel):
   xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Every request needs this token — it's what stops random web pages from reaching the bridge. It's stored in bridge/.inspector_token; delete that file and restart the bridge to rotate it.

2Configure the side panel

  1. Click the extension icon in the toolbar — the side panel opens.
  2. Open settings (⚙) and fill in:
    • Project path — absolute path of the repo Claude should edit, e.g. /Users/you/Projects/my-app
    • Bridge URL — leave http://localhost:3131 unless you changed the port
    • Auth token — paste the token from step 1
  3. Hit Save.
  The dot in the panel header turns green when the WebSocket to the bridge is connected.   Red with “bridge up · set token” means the bridge is running but the token is missing or wrong.

3Use it

  1. Open the page you're working on — ideally your local dev server.
  2. Click ⊙ Select element (or ⊙⊙ Multi-select) and click element(s) on the page. In multi-select, finish with Enter (Esc also confirms what you picked).
  3. Each selected element appears as a card with its selector, a cropped screenshot and — on React/Vue dev builds — the source file and line that rendered it.
  4. Pick a mode:
    • ✏️ Edit — Claude can read and modify the project files.
    • 🔍 Explain — read-only: Claude can only Read/Grep/Glob, useful to understand unfamiliar code.
  5. Optionally enable Verify after edit: when the task finishes, the bridge reloads the tab, re-captures the element and asks Claude to double-check (and fix) its own change.
  6. Type a prompt and hit Send (⌘+Enter works too). Progress streams into the Activity log; a banner appears on the page when the task completes.

After a task

  • View diff — the git diff of the files the task touched.
  • ↩ Undo task — stashes those changes (git stash: recoverable with git stash pop).
  • History — click any previous prompt to reuse it.

4Optional: Claude Code in your terminal (MCP)

Register the bridge's MCP server once, and terminal Claude Code sessions can see what you selected in the browser:

claude mcp add inspector -- node /abs/path/to/claude-code-inspector/bridge/mcp-server.js

Then just say “look at the element I selected in the browser”. The MCP server also exposes the companion tools: list_my_browsers, find_browser and focus_browser tell your Chrome profiles apart (each profile running this extension announces its windows and tabs to the bridge) and bring the right one to the foreground.

Privacy: the tab list only ever goes to your local bridge, only when something changes, and URLs of sensitive sites (password managers, payment providers, Google accounts) are redacted. The list is configurable via the sensitiveDomains key in the extension's storage.

5Troubleshooting

SymptomFix
bridge offlineThe bridge isn't running or the URL/port in ⚙ settings is wrong. Start it with node server.js in bridge/.
bridge up · set token / bad tokenPaste the token printed at bridge startup into ⚙ settings. To rotate it, delete bridge/.inspector_token and restart the bridge.
Cannot inspect this pageChrome blocks extensions on chrome:// pages and the Web Store. Use a normal page.
Project directory not foundThe project path must be absolute and literal (no \  escapes) and the folder must exist.
No screenshots / verify fails on non-localhost pagesDefault site access covers localhost only. Grant broader access from chrome://extensions → Claude Code Inspector → Site access.
Claude answers with stale contextSessions persist per project. Use Reset session in ⚙ settings to start fresh.
Heads-up: in Edit mode Claude runs with auto-accepted edits inside the project you configured. Point it only at projects you're happy to let it modify — that's what Explain mode and Undo task are for.
